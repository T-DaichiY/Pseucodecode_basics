13. Linear Search
Key idea: Use a BOOLEAN flag called Found. Start it as FALSE and stop as soon as it becomes TRUE, so you do not keep searching a list you have already finished with.
1Sample Reference
DECLARE Titles : ARRAY[1:5] OF STRING
DECLARE SearchTitle : STRING
DECLARE Counter : INTEGER
DECLARE Found : BOOLEAN

// Hardcode the 5 titles into the array (no INPUT yet)
Titles[1] <- "Comedy Night"
Titles[2] <- "Drama Files"
Titles[3] <- "Mystery Manor"
Titles[4] <- "Action Zone"
Titles[5] <- "Sci-Fi World"

// Found starts FALSE, Counter starts at the first position
Found <- FALSE
Counter <- 1
INPUT SearchTitle

// Keep checking one position at a time until found or list ends
WHILE Counter <= 5 AND Found = FALSE DO
  IF Titles[Counter] = SearchTitle
    THEN
      // Match! Set Found to TRUE so the loop stops
      Found <- TRUE
    ELSE
      // No match yet, move on to the next position
      Counter <- Counter + 1
  ENDIF
ENDWHILE

// Report the result once the loop has stopped
IF Found = TRUE
  THEN
    OUTPUT "Found at position ", Counter
  ELSE
    OUTPUT "Title not found"
ENDIF

14. Bubble Sort
Key idea: Compare each pair of neighbouring elements and swap them if they are in the wrong order. Repeat passes through the list until a full pass makes no swaps — the list is then sorted.
1Sample Reference
DECLARE Temperature : ARRAY[1:6] OF INTEGER
DECLARE Index, First, Last, Temp : INTEGER
DECLARE Swap : BOOLEAN

// Hardcode the 6 temperatures into the array (out of order)
Temperature[1] <- 18
Temperature[2] <- 25
Temperature[3] <- 14
Temperature[4] <- 30
Temperature[5] <- 21
Temperature[6] <- 17

// First and Last mark the part of the array still being sorted
First <- 1
Last <- 6

// Keep making passes until a full pass makes no swaps
REPEAT
  // Assume this pass is sorted until a swap proves otherwise
  Swap <- FALSE
  // Compare every neighbouring pair in the unsorted part
  FOR Index <- First TO Last - 1
    IF Temperature[Index] > Temperature[Index + 1]
      THEN
        // Swap the two values using Temp as a holding space
        Temp <- Temperature[Index]
        Temperature[Index] <- Temperature[Index + 1]
        Temperature[Index + 1] <- Temp
        Swap <- TRUE
    ENDIF
  NEXT Index
  // The largest remaining value is now in place, so shrink the range
  Last <- Last - 1
UNTIL (NOT Swap) OR Last = 1

// Output the sorted array, one value at a time
FOR Index <- 1 TO 6
  OUTPUT Temperature[Index]
NEXT Index

4Scenario Question
Why is a trace table useful?
Show Answer
A trace table lets you manually work through (dry run) an algorithm step by step, recording how each variable's value changes and what is output at each stage. This helps you find logic errors and check that an algorithm does what it is meant to do, without needing to actually run it on a computer.
